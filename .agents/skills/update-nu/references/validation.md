# update-nu 场景验收

用于修改技能后的行为审查，不是每次发版都要重新执行的固定测试清单。
可使用临时 Git 仓库、模拟的发布记录和版本输出；不要为测试降级本机 Nu，
或向真实文档/源码仓库写提交。清楚区分场景推演与真实 CLI 验证。

| 输入状态                                                   | 必须观察到的决策                                                                 |
| ---------------------------------------------------------- | -------------------------------------------------------------------------------- |
| `.env` 提供两路径，但环境变量覆盖其中一个                  | 各键独立解析，环境变量优先，未执行 `.env` 内容；相对路径从目标仓库解析。         |
| docs HEAD 在旧版，工作区有新的未提交草稿；fetch 成功       | 固定 FETCH_HEAD SHA；只从该树读取日志/博客，忽略本地草稿，不 stash/reset。       |
| fetch 失败，但本地 origin/main 存在                        | 不把旧跟踪引用当成本轮已同步；停止最新版本更新并报告失败。                       |
| 最新博客是 0.116.0，官方最新稳定版是 0.116.1，本机 0.116.0 | 门禁失败并提示升级；不能因为博客版本匹配就继续。                                 |
| 同上，本机 0.116.1                                         | 门禁通过，以博客和 0.116.1 release body 为素材，明确实测为 0.116.1；不要求降级。 |
| 草稿博客为 0.117.0，稳定版仍为 0.116.1                     | 忽略草稿的版本门槛；本机 0.117.0-dev 不能标为稳定版实测。                        |
| 显式二进制路径与 PATH 的 nu 版本不同                       | 门禁、父进程和子进程均使用选定二进制；低版本门禁不依赖新版 Nu 命令。             |
| 新增第四份指南（含 0.99 和 0.100）                         | 按数字版本排序，保留最新三份；移动旧文档并修复所有相对链接，索引保持准确。       |
| 归档目标同名但内容不同；或同一更新重复运行                 | 不覆盖冲突文件；重复运行不新增重复指南、不重复移动，也不抹掉历史实测证据。       |
| 死锁复现不结束，或旧缺陷在新版本被修复                     | 有界超时且清理自建进程；将修复落实为版本限定的断言和指导，而非跳过测试。         |

反馈至少包含：具体场景、实际决策、与预期的差异，以及仍未验证的分支。
真实发版的版本/SHA/命令/结果应保存在对应迁移指南，避免把某次发版数据
永久塞进本工作流。技能语法校验通过不能替代这些行为检查。
